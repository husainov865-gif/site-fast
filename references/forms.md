# От демонстрации к настоящим заявкам

## До публикации

Макет работает офлайн и ничего не отправляет. При публикации скопируй assets/form-service в release/service, выполни там npm install и сохрани полученный package-lock.json. Используй поддерживаемую версию Node.js >=22. Пример предназначен для одного процесса за локальным Nginx, без вложений и сложных квизов. Расширения полей согласуй и проверь на обеих сторонах.

Скопируй .env.example в /etc/site-fast/PROJECT.env на сервере, вне public. Владелец передаёт секреты через защищённый механизм окружения или сам заполняет файл по SSH. Права 600 для владельца либо 640 с группой сервисного пользователя. Не включай .env в архив публикации.

Параметры: MAIL_ENABLED=true включает реальную отправку; SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, MAIL_FROM, MAIL_TO; ALLOWED_ORIGIN — точный HTTPS origin без пути и завершающего слеша. SMTP_SECURE=true обычно для порта 465; для 587 используется STARTTLS. Не отключай проверку TLS. PORT должен совпадать с Nginx и быть свободным. Базовый шаблон использует 3100.

Письмо отправляется на серверно заданный адрес. Посетитель не задаёт получателя, отправителя или тему заголовками. Форма отправляет JSON на /api/lead:

```json
{"name":"ТЕСТ","contact":"test@example.com","message":"Проверка формы","formId":"hero","page":"/","consent":true,"extra_note":""}
```

contact — телефон или email. extra_note — необязательное скрытое поле; заполнение добавляет пометку к письму, а не молча теряет заявку. Поле должно быть исключено из табуляции и автозаполнения. formId и page помогают понять источник заявки; этот пример не собирает UTM автоматически.

Клиент: проверь поля, заблокируй кнопку на время POST, покажи понятную загрузку, после ответа разблокируй. На 200 со status=smtp_accepted покажи «Заявка отправлена. Если ответа не будет, свяжитесь с нами…» с настоящим контактом. На 4xx/5xx или сетевой ошибке сохрани введённое и предложи повторить либо связаться напрямую. Не показывай успех в finally и не повторяй отправку автоматически. Таймаут может произойти после принятия письма: точно-однократная доставка этим примером не гарантируется.

## Сервер и пределы примера

Сервис слушает только 127.0.0.1. Nginx заменяет X-Real-IP на реальный адрес прямого посетителя. Если перед Nginx есть CDN/другой proxy, сначала настрой доверенные адреса на Nginx. Не открывай Node-порт наружу.

Обработчик проверяет Origin, JSON, лимит тела, поля, согласие и частоту по IP. Лимит хранится в памяти одного процесса, сбрасывается при перезапуске и не является распределённой защитой. Origin не заменяет защиту от ботов: небраузерный клиент может подделать его. Для повышенного спама добавь защиту под задачу и протестируй её доступность.

Этот стартовый профиль отправляет письмо синхронно и не хранит постоянную очередь заявок. При ошибке отправки возвращается ошибка, посетитель сохраняет возможность повторить. Если бизнес требует сохранения каждой заявки при отказе почты, ДО запуска добавь постоянное хранилище/очередь, доступ владельца, правила хранения, повторов и защиты от дублей. Не обещай «заявка не потеряется никогда» для базового примера.

SMTP accepted означает принятие адреса почтовым сервером, а не попадание во входящие. Проверяй SPF/DKIM/DMARC по инструкции выбранного провайдера; не создавай вторую SPF-запись и не перезаписывай почту домена. Проверку фактического получения завершает владелец. Не записывай содержимое заявок или SMTP-пароли в логи.

Реквизиты, тексты политики, основания обработки, регионы хранения и используемые сервисы предоставляет/подтверждает владелец. Не публикуй шаблонные документы как юридически проверенные. Для регулируемой деятельности и спорных требований нужна отдельная актуальная проверка.

Документация транспорта: [Nodemailer SMTP](https://nodemailer.com/smtp). Параметры окружения Node: [--env-file](https://nodejs.org/api/cli.html#--env-filefile).
