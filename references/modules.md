# Реальные возможности текущей установки
При установке, возобновлении чата, изменении состава модулей и перед запросом модульной функции выполни `node tools/module-status.mjs .`. При двух агентах используй активный `--agent codex|claude`. Не определяй наличие по памяти, названию ZIP или словам «я купил». Реестр сверяется с реальными файлами, manifest, версией базы, entry, ресурсами и инструментами. Не исполняй неизвестные/внешние пути.

## Когда пользователь ещё не знает о комплекте
bundleAware=false и надёжная проверка (чистая бесплатная установка): бесплатный процесс HTML/сервер. Сам не упоминай платные дополнения, комплект, SEO-ветку, Figma-генерацию и Тильду, не перечисляй отсутствующие пакеты и не задавай вопрос «с SEO или без». Обычные ссылки/макеты Figma как исходные материалы разрешены и не означают запрос платной генерации. Чистая установка не должна начинаться с рекламы дополнений.
Если пользователь сам попросил платную функцию, ответь только по ней: «Для вёрстки на Тильде нужен site-fast-Tilda. Сейчас модуль не установлен. Установите его, затем продолжим». Не перечисляй остальные дополнения и не подменяй запрос серверным сайтом.

## После установки хотя бы одного модуля
bundleAware=true означает осведомлённость о комплекте по локальным следам установки, не подтверждение оплаты. Три модуля входят в ОДИН приобретаемый продукт: site-fast-SEO, site-fast-Figma, site-fast-Tilda. Они устанавливаются независимо в нужный проект. Не предлагай повторную покупку недостающего пакета. Не считай весь комплект установленным только потому, что найден один модуль.
До структуры предложи нужные варианты по project-routing.md, учитывая уже известные ответы. Если выбрана отсутствующая функция, коротко назови модуль, необходимость установки из комплекта и ближайший шаг; заблокируй только зависимую стадию. Не ограничивай список вариантов только теми модулями, которые уже установлены, иначе пользователь не сможет выбрать установку недостающего.

| Запрос | Требуется |
|---|---|
| SEO-проработка/SEO-аудит по нашему сценарию | готовый seo |
| Создание/генерация редактируемого макета нашим плагином | готовый figma |
| Вёрстка согласованного ZIP на Тильде | готовый tilda, затем MCP и явное поручение переноса |
| Перенос уже готового согласованного ZIP | figma не обязателен: проверка ZIP входит в tilda |
| Работа с брифом/брендбуком/референсом или Figma как исходником | базовый сбор материалов, без требования модуля за саму ссылку |

## Правильный ответ на состояние
absent: «Модуль X не установлен. Установите X из вашего комплекта, затем продолжим». Если архив уже предоставлен и установка поручена — сам запусти штатный установщик. Иначе попроси архив/путь, не ключи. Не устанавливай остальные модули без необходимости.
unregistered: файлы найдены, но установка не завершена; завершить штатным установщиком с резервной копией. Не объявлять модуль готовым по папке.
broken: установлен не полностью/не хватает компонентов; назвать конкретное, восстановить из пакета. Не предлагать покупать заново.
environment_incomplete: модуль установлен, но не хватает зависимостей; сам выполнить доступное восстановление (SEO: npm ci в tools/site-fast-seo), затем CLI smoke-check и повторная проверка. Это не отсутствие модуля.
incompatible/unavailable: обновить базу/модуль; старая заглушка не равна рабочей функции.
other_agent/needs_agent_selection: использовать активную копию; уточнить один раз, не брать инструкции из другого проекта или агента молча.
unknown/REGISTRY_INVALID: не утверждать «все модули отсутствуют»; восстановить реестр с резервной копией по достоверным файлам/установщикам, не теряя остальные записи.
ready: локальные файлы/зависимости готовы. MCP, права аккаунта, Figma Desktop, шрифты и согласование конкретного ZIP проверяются отдельно в реальном окружении. Установленный tilda при недоступном MCP требует подключения по авторской инструкции, а не переустановки/покупки модуля.

После установки/восстановления ещё раз проверь module-status и plan-route; продолжай сохранённую задачу с нужного шага, не проси повторять бриф и не теряй уже выданное поручение. Не повторяй сообщение о том же блокере после каждого ответа. Предложить другую ветку можно, переключить — только по решению пользователя. Независимые материалы можно готовить параллельно; «готово к полному маршруту» при блокере не объявлять.

Установщик сохраняет bundleAware=true в PROJECT-MODULES.json, чтобы осведомлённость о комплекте не исчезала при отключении/удалении модуля. Этот флаг не включает функции: каждую функцию всё равно проверять по её реальной установке.
