# Провайдер, ОС и сервисы
Прочитать только для выбранного размещения. Перед действиями проверить актуальную официальную документацию провайдера, ОС, ACME-клиента и SMTP-сервиса. Нельзя переносить цены/порты/методы из одного сервиса на все.
Для любого VPS: публичные IP и IPv6; доступ/SSH host key; inbound 80/443/SSH; ограничения outbound SMTP; DNS где NS; snapshot/backup; панель и её конфиги; сертификат/renew; лимиты диска/ресурсов. Записать выводы и ссылки в docs/deployment.md.
Timeweb Cloud: исходящий SMTP может блокироваться по умолчанию, включая 465/587; сначала реальный TCP/TLS-тест. Разблокировку через кабинет/поддержку выполняет владелец. Это не ошибка пароля и не причина открывать входящий backend-порт. https://timeweb.cloud/docs/cloud-servers/limitations
Другой провайдер: выяснить его ограничения, не просить «разблокировать SMTP» без фактической проблемы. Если SMTP недоступен, согласовать поддерживаемую транзакционную почту/API либо временно отключённые формы, не менять способ незаметно.
Mail.ru: применимый пароль приложения и параметры по https://help.mail.ru/mail/login/mailer/ ; у других почтовиков — их параметры и инструкции, не обязательный Mail.ru для всех.
ACME: https://letsencrypt.org/docs/challenge-types/ и https://certbot.eff.org/instructions . При панели использовать поддерживаемый механизм, не ставить конфликтующий сертификатный менеджер.
Проверено 01.11.2026; при выполнении перепроверить актуальность.
