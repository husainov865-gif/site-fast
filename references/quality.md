# Проверки и честный отчёт

Сохраняй результат в docs/checks.md. Статусы: ПРОЙДЕНО, ОШИБКА, НЕ ПРОВЕРЕНО, НЕ ПРИМЕНИМО. Для каждого пункта укажи дату, страницу, способ и доказательство. Не отмечай пункт по факту наличия кода.

## Перед показом

1. Все страницы и блоки из задания есть; факты сверены с источниками, заглушки видны и перечислены. Фирменный стиль и решения из референсов отражены.
   Перед разработкой прочитаны актуальные «Структура сайта.md» и «Фирменный стиль.md», критичные вопросы разрешены. check-materials проверяет форму документов, но не доказывает, что агент учёл все исходники.
   Ссылки в документах требуют проверки первоисточника: для Figma сверены точные фреймы и роль макета; наличие URL не равно просмотру. Полная перепись визуального источника в Markdown не требуется.
2. preview/index.html открывается двойным щелчком без интернета. Переходы на внутренние страницы, изображения, CSS, JS и шрифты работают в этом режиме. Отдельно проверь режим офлайн в браузере.
3. Автоматический обход всех локальных HTML: `node tools/site-audit.mjs preview --out reports/preview`. Ширины: 360, 390, 430, 768, 1280×690, 1440×900. Скриншоты нужно открыть и просмотреть. Дополнительно проверь границы адаптивных переключений и длину контента.
4. CSS: `node tools/css-audit.mjs preview --out reports/css-preview.json`. Исправь ошибки синтаксиса; повторение свойства может быть намеренным fallback. Этот скрипт ничего не удаляет и не доказывает отсутствие проблем каскада.
5. Вручную/браузерным сценарием проверь каждую строку таблицы взаимодействий: открыть/закрыть меню, все вкладки, ссылки, модалки, клавиатуру, состояния формы. Скрипт site-audit не нажимает кнопки и не отправляет заявки.
6. Проверь читаемость, контраст, подписи, фокус, кадрирование, пересечения, обрезку текста, липкие элементы, масштаб текста и reduced-motion. Автоматический скриншот не означает, что эти пункты пройдены.
7. В макете отправка демонстрационная. Убедись, что сети не отправляется POST и пользователь не видит ложного сообщения о доставке.

## После публикации

- Сравни согласованный макет с релизом. Изменения перечислены, дизайн сохранён.
- Проверь каждый URL отдельно: `node tools/site-audit.mjs https://ВАШ-ДОМЕН/ --out reports/live-home`. Для URL аудит проверяет одну страницу, а не весь сайт. Используй полный перечень из docs/brief.md.
- Проверь HTTP→HTTPS, канонический домен, сертификат, автопродление, настоящую 404, старые адреса и отсутствие цепочек/циклов редиректов. Не любой старый URL нужно перенаправлять: используй migration.md.
- Проверь загрузку всех ресурсов и отсутствие ссылок на локальные файлы, превью-домен, чужие контакты. Секреты и документы проекта не доступны через веб.
- Проверь меню и формы на рабочем домене. По одной помеченной тестовой заявке из каждой формы отправь указанному владельцем получателю. Проверь неверные данные, отказ SMTP, повторный клик и 429; не создавай массовую рассылку.
- Запиши отдельно: API принял запрос; SMTP принял адрес получателя; владелец подтвердил письмо во входящих или спаме. Если письмо не найдено — доставка не подтверждена. Тест SMTP с подставным транспортом является только локальной проверкой кода.
- На публичной версии проверь title/description, h1, canonical, OG, favicon, robots.txt, sitemap.xml. Индексацию включай согласно «Структура сайта.md» и согласованному плану docs/deployment.md, убери случайный noindex. В sitemap только реальные индексируемые адреса.
- Счётчики, цели, поисковые кабинеты и мониторинг подключай только если указаны в задании. Цель формы — после успешного ответа, не на клик. Показатели скорости измеряй и сообщай ограничения измерения.
- Реальное устройство проверяет владелец, если агенту доступна только эмуляция. Не обозначай эмуляцию как проверку реальным телефоном.

Коды утилит: 0 — автоматических ошибок не найдено, предупреждения требуют просмотра; 1 — найдены ошибки сайта/CSS; 2 — неверный запуск или сбой окружения. При коде 2 результат не является успешной проверкой сайта.
